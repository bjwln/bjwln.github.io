# 博客浏览量+评论功能故障排除记录

## 架构

```
博客页面:  www.tysweb.site → Cloudflare 代理 → Vercel（托管 Hexo 静态页）
Worker:    counter.tysweb.site → Cloudflare Worker（numberofvisitors）
数据库:    Cloudflare D1（number_of_visitors）
前端脚本:  page-counter.js + comments.js，通过 Butterfly 主题 inject 注入
```

**为什么有两个域名：** 博客在 Vercel 上，后端逻辑在 Cloudflare Workers 上，不同平台 → 不同域名 → 需要 CORS。

## 故障现象

1. 博客 API 全部 404（`/api/pv`、`/api/visit`、`/api/comment` 等）
2. 浏览器 CORS 报错：`No 'Access-Control-Allow-Origin' header is present`

## 根因 1：Worker 部署代码过旧

本地 `count-worker/src/index.js` 包含完整功能（浏览量+评论），但 Cloudflare 上部署的是旧版 Worker，没有这些 API 路由。

**修复：** `wrangler deploy` 重新部署。注意部署后可能需要等 Cloudflare 边缘网络传播，或重新部署一次确保生效。

## 根因 2：CORS 预检被 Cloudflare 边缘缓存

浏览器出于安全策略，跨域请求（`www → counter`）会先发 OPTIONS 预检请求。"服务器得点头同意"（返回 `Access-Control-Allow-Origin`）才能放行。

旧版 Worker 返回的 OPTIONS 响应没有 CORS 头，且 Cloudflare 缓存了这个响应。即使后来部署正确代码，部分边缘节点仍返回旧缓存。

**修复（两处代码修改）：**
- CORS 常量加 `'Vary': 'Origin'` — 让缓存区分不同来源
- OPTIONS 响应加 `'Cache-Control': 'no-cache, no-store, must-revalidate'` — 禁止缓存预检响应

## 关键知识点

- **CORS（跨域资源共享）：** 浏览器安全机制。不同域名间的 fetch 请求需要服务器在响应头中明确允许。
- **预检请求（Preflight）：** POST + `Content-Type: application/json` 等"非简单请求"，浏览器会先发 OPTIONS 试探。
- **Cloudflare 边缘缓存：** 不只是页面/CDN 文件会被缓存，API 响应（包括 OPTIONS）也可能被缓存。需要显式设置防缓存头。
- **wrangler 部署：** `wrangler deploy` 上传代码+更新路由。版本可能因 Cloudflare 传播延迟需多次部署。
